# Sol today (store pack, track RS)

This pack is published on Explorers and is **not** built into SSE4. Nothing under `store-packs/` is loaded by the kernel or the app; the onboarding tour fetches this pack from the store to teach loading a pack (Alex, 23 Nov 2026).

- `catalogue.json` is generated: `python3 -I scripts/spaceflight/import_gcat.py <gcat tsv dir> store-packs/sol-today`. Do not edit it by hand.
- `stations.json` is authored.
- `parts.json` is generated by `scripts/spaceflight/build_parts.py`; `craft.json` is written by hand from cited sources.
- `logs/` holds one flight log per construct (craft, stage, booster, tank, lander, probe), generated by `python3 -I scripts/spaceflight/build_logs.py` from the sources it names; `crates/sse-nav/tests/sol_today_logs.rs` checks them. Do not edit them by hand.
- `logs/departed/` holds one flight log for every other payload that left Earth orbit (462), generated from GCAT's phase tables by `python3 -I scripts/spaceflight/build_departed_logs.py <GCAT tsv dir>`: each phase's shape, inclination, bodies and dates, with the orientation estimated (fudge register, "Real spaceflight"). Each log carries its GCAT id in `gcat`.
- `logs/earth-orbit/` holds one log per station core and per human spaceflight vehicle record (770), from the same script: GCAT's first phase (satcat) as one orbit, then how it ended (reentered, landed, docked); a flight that docks lands or burns up at GCAT's end of mission.
- `crews.json` holds everyone who has been above 80 km (792, two of them chimpanzees) and each leg of their flights (3,314): who, from when to when, aboard which craft or station (with its log here, or null for suborbital hops), in what role. Who was in space at any moment is every leg covering it; `in_space` is that count as steps through time. Short flights carry `peak_km`, so the pack value `edge_of_space_km` (100) can mark those between McDowell's 80 km and it. Generated by `python3 -I scripts/spaceflight/build_crews.py <folder with McDowell's astro.tsv and segments.tsv>`; do not edit by hand.
- `in-memory.json` holds those who died on a flight (6 losses), preparing to fly (8) or in ground work (3), each with two or more sources and one plain sentence of fact; the people it names carry a `death` in `crews.json`, and those who died before they could fly join `crews.json` with no legs. Written by the same script (`scripts/spaceflight/in_memory.py`, Wikidata facts in `in_memory_wikidata.json`). No name is guessed. Alex, 25 Nov 2026: "stay restrained and respectful - one place we don't joke".
- `memorials.json` holds real memorials in space, each with two sources. So far the 21 numbered asteroids named for those in `in-memory.json` (Wikidata "named after" and the Minor Planet Center number, with each orbit from JPL Horizons as heliocentric ecliptic J2000 elements), written by `scripts/spaceflight/memorials.py` from `memorials_sources.json` (`--fetch` queries again). Named craters on the Moon, the hills on Mars named for Columbia's crew, objects left (the Fallen Astronaut at Hadley) and remains carried wait for their second sources.
- `logs/index.json` lists every log once (construct, path, name, GCAT id, first and last time), written by build_crews.py, so a viewer fetches only the logs it needs.
- `pack.json` carries the pack's calendar (Gregorian, days counted on the universe clock).
