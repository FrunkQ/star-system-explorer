# K4: flow documents, validation, scheduler, solve nodes, explain traces

Status: done (18 Nov 2026).

## What was built
Crate `sse-flow`: atom declarations (ports with dimensions and validity ranges, parameters with allowed ranges, cost class, citations, explain text), the `Atom` trait and registry, JSON flow documents (`sse.flow/1`) with content hashes, a validator that reports every problem at once, a deterministic scheduler, evaluation with validity labels and work units, solve nodes, explanation bundles with three lenses, and in-document golden cases. Ten toy atoms and a ten-node fixture flow (`tests/fixtures/flows/toy-ten.json`).

## Design sections implemented
H6.2 and H6.5. Choices the design left open:
- Wires check dimensions, not kind names, so `star.luminosity` may feed any power input (H5.2 says "connecting mismatched dimensions is a validation error").
- Scheduler: Kahn's algorithm with the ready set ordered by node id, so evaluation order never depends on document order.
- Solve node: a residual atom (one output named `residual`), an unknown input, a bracket and a fixed bisection iteration count (default 80). Fixed count is the deterministic stopping rule; bisection needs no derivative and cannot diverge. Brent or Newton can be added later as further methods.
- Validity: `in-range` < `extrapolated` < `impossible-input`, worst upstream label wins; extrapolated lists which ports were out of range.
- NaN or infinity from any atom or input is an evaluation error (ADR 0002).
- Boxes (named sub-flows) are not in K4; they come with the flow editor (U3) and need only a document-level expansion before compile.

## Results
- The ten-atom flow compiles, evaluates and passes its own golden case for Sun and Earth: Teff 5772 K, insolation 1361 W/m², T_eq 254.6 K, surface 286.3 K (solve), year 365.256 d, g 9.798 m/s², v_esc 11.18 km/s, density 5.495 g/cm³ (equatorial radius).
- Every published output has an explanation; every derived input's `explanation_ref` resolves, so "why" can walk back to the flow inputs.
- Rejected with readable messages: a cycle (`cycle through nodes a, b`), a mass wired into a length (`dimension mismatch: [kg] into [m]`), an unwired input, a quantity published twice, a parameter out of range, an unknown atom, a published dimension that contradicts its kind.
- Validity: a 40 solar-mass star marks luminosity and everything downstream `extrapolated` and leaves gravity `in-range`; an `authored-impossible` input marks only its downstream.
- Golden: published values hash `a063fe36…2d1d5a`; flow document hash `327fac6b…675729`.

## Known limits
- Toy atoms are fixtures, not physics. Their two main-sequence power laws are deliberately crude.
- Non-scalar wire values (curves, distributions) are not yet supported.
- Flow values are evaluated in the wasm build only from K6 onward (the K6 contract tests run this flow through the worker).
