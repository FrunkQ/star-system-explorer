# K5: pack manifest, stack resolution, one-publisher rule, fictional labels

Status: done (18 Nov 2026).

## What was built
Crate `sse-pack` (new crate; ADR 0001 explains the addition): `sse.pack/1` manifests (JSON), and `resolve(stack, kernel_version)` which validates a bottom-to-top stack and returns the active quantity kinds, units, flows, a publisher for every (hook, quantity kind), the fictional quantity kinds, and a stack hash. Problems are collected and rendered by `report()` as a numbered, readable list.

## Design sections implemented
H7 (manifest, layering, stacking rules, fictional flag). Choices the design left open:
- The one-publisher rule is per (hook, quantity kind): the same kind may be published at different hooks (e.g. a star's luminosity and a lamp's).
- An override names the flow, its pack and the pack's version range (`replaces: [{flow, pack, range}]`); a higher pack providing a flow id that already exists without `replaces` is an error, as is a `replaces` whose range does not match the stacked version.
- Quantity kinds may be re-declared by a higher pack only with the same dimension; units may be re-declared only identically.
- Fictional propagation is computed over the whole stack to a fixed point: a flow's published kinds are fictional if its pack is fictional or any of its input kinds is. K6 attaches the label to every derived value it returns.
- Rules, sifters, data views, screens, skins, vocab and catalogues are carried in `provides.other` (hashed, not yet interpreted).

## Results
- A base pack holding the toy kinds and the ten-atom flow resolves with exactly 10 publishers; the stack hash is reproducible.
- A rival pack publishing the same quantity at the same hook is rejected: "Pack stack rejected: 1 problem … only one publisher is allowed (use `replaces`)".
- A declared override (thicker greenhouse) replaces the base flow and becomes the publisher; the same override written for `^2` of the base is refused with the version shown.
- A fictional "force" pack marks its outputs fictional, and a separate real-physics pack consuming them is marked fictional too; base outputs stay real.
- One stack with eight different mistakes reports all eight (bad id, bad version, kernel range, missing requirement, unit and kind redefinition, duplicate pack, silent flow override).
- Every flow in a resolved stack compiles against the toy atoms.

## Golden hashes
None added (stack hashes are tested for reproducibility; a pinned stack hash comes with the base-physics pack in P1).

## Known limits
- Packs are single JSON documents with flows inline; multi-file packs and signing come with X2.
- Requirements are checked against packs lower in the stack only (layering), so order matters by design.
