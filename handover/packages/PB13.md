# PB13: layouts on the board (parts 1 and 2a)

Thread "Build Run desk playbook and players' side", 24 Nov 2026. Design `handover/design/SSE4-playbook-and-switchboard-design.md` section 7.4 (accepted), "simplify as we go": one editor for new and existing layouts.

## What
- ui-contract `layouts.ts`: `SHIPPED_LAYOUTS` (Bridge, Bridge in 3D, Tarn survey report, Landing), `ARRANGEMENTS` (One picture, Picture and side panels, Two by two, Report page, Blank, each a screen layout with fixed areas), `arrangementOf`, `layoutIdFor` (`mine.<name>`), `rearrange`, `sorted`, `moveBox`, `swapBoxes`, `addBox`, `removeBox`, `blankLayout`, `copyLayout` (a shipped layout is edited as a `mine.` copy and leaves the rail behind), `layoutsFrom`, `keepLayout`.
- Kept with the campaign: `workspace.layouts` and `CampaignSave.workspace.layouts` (older saves have none).
- Players' screens get them: `Manifest.layouts` and the `state` message carry the made layouts; `PlayerReplica.layouts`. The players' page resolves a `mine.` id against them, and reloads its screen when the role's layout changes, or when the made layout it names changes. Two loads in flight: only the last one asked for is used. This also mends a PB7 gap: a layout chosen on the role card now reaches screens already joined.
- Switchboard: each role heading has its layout ("Bridge ▾"), which opens `run/LayoutPicker.svelte`. The picker lists every layout (shipped and made) and changes the role's screens at once. "Edit this layout…" and "+ New layout…" open the same `run/LayoutEditor.svelte`: Name, Arrangement, the boxes (each a part with its own controls as checkboxes (AT13), arrows to move, × to remove, drag one onto another to swap), "+ Box", and a live preview. The preview is a still picture of what the role knows of the place in view. "Save and use" keeps the layout and gives it to the role.
- Presets: a Show step may name a layout (`show.layout`; `showOf` puts it on `Shown.screen`). "On the layout" in the preset monitor; going back returns the role to its own.
- The role card's layout list is the same `SHIPPED_LAYOUTS`.
- Part 2a, a box that holds a bookmark: `ScreenItem.place` (`BoxPlace`: scope, focus, title; checked to be addresses) is copied from the bookmark into the layout, so players need no bookmarks of their own. The editor's "Whatever is sent ▾" on each box lists the bookmarks. On the players' page each placed box draws that place's scene for the screen's audience (`places`, built beside the main scene), about the bookmark's selected thing, and its name sits over the box (`data-placed`, `data-place-title`); the other boxes draw whatever is sent.
