## What was built

- `handover/packages/MP0-typed-copies.txt`, the ledger. It lists every constant of nature, reference value and
  material number still typed outside the sheet, one line per copy, tab separated:
  1. the file;
  2. the sheet row it should read: `constant:G`, `substance:h2o/molar_mass`, `mixture:dry-air/molar_mass`,
     `isotope:k40/half_life_s`, `element:h/atomic_mass`, or `new:...` where the sheet has no row yet;
  3. the source line, trimmed (code), or `json:<path>` (a pack property).

  There are no line numbers, so an edit elsewhere in a file leaves the ledger alone. Lines match as a multiset:
  a line typed three times is listed three times. The sheet itself (`packs/base-reference`,
  `crates/sse-reference`) and test code are not counted.
- `scripts/audit-matter.py --ledger FILE [--base REF | --base-ledger FILE]`, the check. It fails (exit 1) on:
  - a typed copy that is not in the ledger;
  - a ledger line whose copy is gone (delete the line);
  - a ledger that gained a line against the base.

  It prints `typed copies left: N`. Exit 2 means it could not run (bad arguments, an unreadable or malformed
  ledger, an unreadable base). Changing a labelled line in place, in the same file with the same sheet row, is
  an edit, not a new copy. When the ledger does not exist at the base yet (this PR), the growth check is
  skipped and the output says so. It runs in about a second, standard library only.
- `scripts/audit-matter.py --write-ledger FILE` writes the ledger from a fresh scan. It was used once here. Run
  again later, it would label new copies, and the growth check against main stops that.
- The scan is MP0's, with two changes:
  - Pack keys that name a model setting or one body's measured fact are not counted (`NOT_MATTER` in the
    script, each with a reason). Examples are an atlas example's bulk density, an absorption line's shape, a
    climate threshold such as `t_ice_k`, and a galaxy's star density.
  - A Rust const that only combines other consts (`GM_SUN / G`, `sse_core::quantity::consts::G`) is not a
    typed copy. One with its own number (`365.25 * DAY`) is.
- `scripts/test-audit-matter.py` covers the package's acceptance tests on a small temporary repo:
  - a new typed density fails, and a new typed constant fails;
  - labelled copies pass, are counted, and name their sheet row;
  - a ledger that grew fails;
  - a stale line fails;
  - shrinking passes and the count drops;
  - an edited line in the same file and row passes;
  - an unreadable or malformed ledger exits 2.
- `scripts/check.sh` runs both, against `origin/main` when that ref exists.

## For every thread

- A new typed constant or material number fails CI. Read the sheet (the reader in Rust, the Look up block in a
  flow).
- When you edit a file listed in the ledger, move its copies to the sheet in the same change and delete their
  lines.
- If you change a labelled line without removing the copy, update its third column.

## CI

The CI step (ubuntu rust job, after the sheet check) is in this package, agreed with the kernel thread:

```
git fetch --depth=1 origin main
python3 scripts/test-audit-matter.py
python3 scripts/audit-matter.py --ledger handover/packages/MP0-typed-copies.txt --base FETCH_HEAD
```

This must run on the pull request's merge ref (the default), so a branch made before main shrank the ledger
does not read as growth.

## Part 2a: one compiled copy (22 Nov)

- **`crates/sse-core/src/sheet.rs`** is generated by `scripts/build-rust-reference.py` from
  `packs/base-reference`. It holds every sheet constant at its unedited value as a `pub const` (the id in
  capitals: `sheet::YR_JULIAN`, `sheet::R_EARTH_MEAN`), plus `ALL` by sheet id. Each value is written in
  Python's shortest round-trip form, so it is the sheet's f64 bit for bit. The audit counts the file as a sheet
  home. `the_compiled_sheet_is_the_base_sheet` (sse-reference) fails when the file is stale.
- **How the sweep moves a copy:** compiled code that needs a constant's unedited value writes
  `sse_core::sheet::NAME`. Code that should follow an edit reads the handle (`sse_core::constants`) or the
  reader. When a copy has a different number from the sheet (`8.314` for `R_gas`, `5.97e24` for Earth's mass),
  moving it changes results, so the move goes in its own commit, with the golden change and its reason in this
  log.
- **`quantity::consts`** now names `sheet` values and types no number, and neither does the `degc` unit. The
  ledger drops its 14 lines, to 580.
- **`read_matter` reads a source by id** (`{table: "sources", id}`), giving its text, DOI or URL and status.
  The chart room asked for this so the Cosmos notes can cite their `src` and `also`.

Goldens: none change.
