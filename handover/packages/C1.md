# C1: axis registry, class records, schemes, SSE 3 classic

Status: done (18 Nov 2026), kernel track, branch `claude/project-thread-dzkz4p`. Classification design section 12, row C1.

## What was built
In `sse-sift`, on the K8 region machinery:
- **Axis registry** (`Axis`, section 3): fact field, scale, span, label, plus `unit`, `divide_by` (a unit change, e.g. kg to Earth masses), `missing` (a value to use when the fact is absent, only for schemes that must reproduce an older classifier), `applies_to`, `explain_ref`, and `provisional` (no V4 flow publishes the fact yet, so it is read as authored or imported). `Axis::value(subject)` is the one reader that region and classic scoring share.
- **Class records** (section 4): `names {physics, plain, story}`, `meaning` (identity or flourish), `gate`, `weight`, `typical`, `needs`, `rarity`, `generate`, `look {mark, colour, image {file, licence, credit}}`, `learn {summary, explain_ref, link}`, `examples [{name, values, expect in|out}]`, `source`, `notes`, `evidence` (science, speculative, fictional). All optional with defaults, so K8 atlases load unchanged.
- **Schemes** (section 6): `Scheme {id, question, scoring: region | classic, tolerance, max_classes, borderline, fallback}`, pack key `provides.other.schemes`, one definition per id across a stack. A scheme with no record scores by region (K8 behaviour).
- **Classic scoring** (`classic.rs`): SSE 3.1's fingerprint classifier reproduced exactly. That covers the band fit with a 15% relative soft edge, the gates, mean x (1 + 0.1 n) x weight, a clean match outranking a partial one (B16), stable pack-order tie-breaks, modifiers at their threshold up to `max_classes`, and the mass fallback. The label carries SSE 3's own output and working (`ClassicWorking`): the class list, fallback, borderline, the top five ranked candidates with each band's fit and the change needed to reach the core, and the modifiers. `Label.nearest` holds the runners-up.
- **Examples as tests**: `Atlas::check_examples()` lists every example that does not come out as it says.
- **Label-change events** (`relabel.rs`): `relabel::record(chronicle, atlas, scheme, address, times)` labels a body from the chronicle's own state at each time and appends `classify.relabel` wherever the base label changes. Each event has `Derived` evidence, `payload.data {scheme, from, to, fit, atlas}` with the atlas content hash, no `set`, and as its cause the last event that set a fact on the body.
- **The "SSE 3 classic" pack** `packs/sse3-classic/pack.json`, generated by `scripts/import-v3-classes.py` from SSE 3.1 `starter-sf/classification.json`:
  - All 72 class ids and 31 axes. Match bands become cores in SSE 3's order (the scorer sums in that order), with a display fringe at the same 15%.
  - `note` becomes `learn.summary`, `range` becomes `typical` (centre and half-width), `formation` becomes `generate`, and images go into `look.image`.
  - SSE 3's real-body test cases (Bennu, Eros, Psyche, 67P, Ceres, GJ 876 b) are the examples.
  - Axes map onto V4 facts where a V4 flow publishes them: `body.mass`, `body.radius`, `body.bulk_density`, `body.escape_velocity`, `orbit.semi_major_axis`, `orbit.eccentricity`, `orbit.period`, `planet.equilibrium_temperature`, `planet.surface_temperature`, `atmosphere.surface_pressure`, `system.age` and `parent`, using SSE 3's own constants. The other axes keep their SSE 3 feature names and are marked provisional. SSE 3's feature-map defaults (no air reads as `atm.main` "None", no water as coverage 0, and so on) are the axes' `missing` values.

## Checks (`cargo test -p sse-sift`)
- **Against SSE 3's own code**: on 3,000 generated bodies (`tests/fixtures/classify/v3-oracle.json`, made by `scripts/v3-classify-oracle.mjs`, which runs SSE 3.1's `classification.ts` in Node), the class lists, base, fallback, borderline flag, candidate order, scores and modifiers all match.
  - The bodies sit around every fingerprint: on edges, outside by up to 25%, with features missing, and with competing fingerprints.
  - Scores are compared to SSE 3's two-decimal display values. Everything else is compared exactly.
- **Every Solar System body gets its expected label**: 18 bodies as V4 facts (`tests/fixtures/classify/solar-system.json`) go through the axis registry and receive exactly the class lists SSE 3 gives the same values, for example Earth earth-analogue, Jupiter ammonia-clouds gas giant plus ringed, Europa subsurface ocean, Neptune ice giant plus ringed.
  - Each label carries its working: the winner's bands and the limiting band.
  - The nearest classes say what would have to change.
- **Class examples pass**. A port of SSE 3's B16 "rigged" case also passes.
- **Relabel events replay from the manifest**: on a warming Earth, the labels go earth-analogue, then silicate at 1 Gyr, then lava at 3 Gyr, and the two events are dated, derived and caused.
  - The same authored chronicle and the same pack give the same manifest id, the same event ids and the same chronicle head.
  - A changed atlas gives other event ids over the same facts.
- **Removing every atlas leaves facts unchanged**: the state at the end is identical with and without relabel events, and an empty atlas records nothing.
- **Same labels on every device**: new golden `tests/golden/classify.json` (Solar System labels, relabel ids, chronicle head). It is checked natively, in Node and in Chromium through `engines_run`.

## SSE 3 quirks kept on purpose (the classic scheme must say what SSE 3 said)
- A body where only modifiers score gets a class list with no base (SSE 3 adds its fallback only to an empty list). The SSE4 label still names the fallback base, and `ClassicWorking.classes` keeps SSE 3's list.
- SSE 3's explanation lists no modifiers when the base is a fallback.
- Some SSE 3 labels are SSE 3's own limits, not science: the Moon reads as a mesoplanet and Ceres as a planetesimal. C2's physical atlas is where that gets fixed. The classic scheme exists to keep V3 labels.
- Classic scoring has no stickiness. SSE 3 re-derives every pass, so its `fit` is SSE 3's score, which can exceed 1.

## Numbers (follow-up to `numbers.md`)
Building the pack showed that the first limit (integral below 1e21 decodes as an integer) made integers too large for i64 and u64, which then could not be written back as JSON (Psyche's mass in kg). The limit is now 2^63, the i64 range: below it any spelling of an integral number is an integer, and from it on every spelling is a float. No golden moved. `numbers.md` is updated.
