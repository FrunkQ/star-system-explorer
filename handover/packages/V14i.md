# V14i part 1: the class gallery's pictures

Reference, Classes: opening a class draws a picture of a world that is that class, in True.

## How
- `ViewSession.classSample(classes, extra)` calls the kernel's `class_sample` (a mid-band world per class on a
  what-if branch). Since kernel PR 592 each sample's address carries the branch and class
  (`sys:class-sample-<n>-<8 hex>`), so a surface cache keyed by address never mixes two calls' worlds.
- `surfaceTiles(system, body, branch?)` reads the sample's six level-0 tiles on that branch (GM only).
- `views/reference/src/class-picture.svelte.ts` reads the face through `readTrueFace` with the branch's doors
  (weather refused: a sample world has none yet), draws it alone with `trueStill` (`renderer/src/true-still.ts`),
  and drops the branch. One drawing at a time.
- `Classes.svelte` changes only at the picture slots agreed with the names thread: the tile's `svg.icon` and the
  card's `data-picture` paragraph. The chart mark stays as the fallback.

## Where the mark still shows (recorded, not this package)
- Small bodies (Eros, Bennu, 67P, Psyche, Arrokoth): samples come back with `radius_m` null; waits on kernel K3
  for small bodies (`packages/K18-describe-star.md`, Open). The renderer skips them rather than read tiles for a
  body with no size (a 67P read ran for minutes in the browser).
- Thick-air worlds: with no clouds the disc draws dark in True (`still.lit` false), so no picture; waits on
  weather for a sample world.
- A player's seat (branches are the GM's) and a device with no GPU.
