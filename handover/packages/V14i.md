# V14i part 1: the class gallery's pictures

Reference, Classes: opening a class draws a picture of a world that is that class, in True.

## How
- `ViewSession.classSample(classes, extra)` calls the kernel's `class_sample` (a mid-band world per class on a
  what-if branch). Since kernel PR 592 each sample's address carries the branch and class
  (`sys:class-sample-<n>-<8 hex>`), so a surface cache keyed by address never mixes two calls' worlds.
- `surfaceTiles(system, body, branch?)` reads the sample's six level-0 tiles on that branch (GM only).
- `views/reference/src/class-picture.svelte.ts` reads the face through `readTrueFace` with the branch's doors
  (weather refused: a sample world has none yet), draws it alone with `trueStill` (`renderer/src/true-still.ts`),
  and drops the branch. One drawing at a time.
- `Classes.svelte` changes only at the picture slots agreed with the names thread: the tile's `svg.icon` and the
  card's `data-picture` paragraph. The chart mark stays as the fallback.

## Where the mark still shows (recorded, not this package)
- Small bodies (Eros, Bennu, 67P, Psyche, Arrokoth): samples come back with `radius_m` null; waits on kernel K3
  for small bodies (`packages/K18-describe-star.md`, Open). The renderer skips them rather than read tiles for a
  body with no size (a 67P read ran for minutes in the browser).
- Thick-air worlds: with no clouds the disc draws dark in True (`still.lit` false), so no picture; waits on
  weather for a sample world.
- A player's seat (branches are the GM's) and a device with no GPU.

# V14i part 2: every class a turning globe, paged (Alex, 24 Nov; 26 Nov on pre-drawing)

## What
- Reference, Classes shows the gallery a page at a time: 12, 24 or 48 tiles ("At once"), with Earlier and Later.
- Every tile on the page wears its class's turning True globe; a class opened shows it larger on its card.
- A globe is one turn drawn once as a strip of 36 frames of 112 px (`renderer/src/true-still.ts` `trueTurn`, the
  same face door, light and finish as `trueStill`), then stepped through by CSS (`.turn`, `steps()`): no GPU, no
  kernel and no script per tile. Reduced motion holds each on its first frame. Spin follows the sample's day sign.
- Live drawing is one class at a time (the class opened jumps the queue; a page left is dropped from it).

## Pre-drawn (Alex, 26 Nov: "we KNOW the composition before we start and it will be static")
- The shipped atlases' sample worlds are fixed by their own examples, so `scripts/build-class-pictures.mjs` draws
  every class once in the built shell and writes `packs/base-presentation/class-pictures.json`
  (`sse.class-pictures/1`: per atlas pack and version, a WebP strip and caption per class, or why there is none).
  About 30 kB a globe. Fetched only when the Classes page first shows a page.
- The set is stamped with a look fingerprint (`scripts/class-pictures-look.mjs`: the renderer's source, the kernel's
  surface, light and world crates, the physics pack and the shipped atlases). The shell build carries the current one
  (`__SSE_LOOK__`, `packages/shell/vite.config.ts`); a set drawn with another look is not shown and the gallery draws
  live, so a renderer change is seen at once. **To bring it up to date: `scripts/build-shell.sh`, then
  `node scripts/build-class-pictures.mjs`** (about 15 minutes headless; `--atlas=<pack id>` for one atlas;
  `--check` says whether it is current). The GM's "Draw again" button redraws the page live on that device.
- `tests/ui/class-pictures.test.ts` checks the set reads and reports (does not fail) when it is out of date, so a
  renderer PR does not go red for it.

## Still the chart mark (and why, in the tile's `data-picture-why`)
- Gas and ice giants, and Venus-like worlds (rocky's best example is Venus, also surface/hot-greenhouse, air/carbon-
  dioxide, habitable/sealed-habitat): their faces come from the weather, and `weather` reads the campaign's line only,
  where a sample world does not exist. **Kernel ask: `branch` on `weather`** (body_conditions on the branch's
  chronicle), which would give these their decks and clouds.
- Small bodies: SSE4 atlas samples have no radius (kernel K3 for small bodies). SSE 3 classic ones do, but a level-0
  tile read for a body a few km across does not return within a minute in Node either (Bennu 248 m, Eros 8 km; Psyche
  108 km takes 6 s), so samples under 50 km are skipped. **Kernel ask: quick level-0 tiles for small bodies.**
