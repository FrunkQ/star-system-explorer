# U20: Copy and paste on the Build desk, part 1 (UI track)

Status: part 1 done 22 Nov 2026. Top-level design 8.2 ("Copy and paste, kept"), V3 parity row "cut, copy and paste anywhere". Part 1 is Copy and reading a paste. Part 2 places the paste in the campaign as one undo step, and waits on two kernel ops (below).

## What it does

- **Copy** (Build desk): the tool bar's Copy button, Ctrl+C on the chart, or More › Copy on a phone. It takes the selected body and everything that orbits it (by parent links, so a planet takes its moons; the star takes the whole system, but never the temperate zone, which follows from the star). The status line says what was copied and which values the physics will work out again where it lands.
- **The clip** is plain text on the clipboard: `sseClip: 2`, the envelope agreed with the Explorers thread (21 Nov), so the site can store and serve the bytes as they are.

  ```
  { sseClip: 2, generation: "v4",
    source: { site, title, url?, creditChain: [] },
    packs: [{ id, version }],            // the stack it was made under, bottom to top
    root: "n0",
    nodes: [{ id, kind, parent }],       // parents first; parent null for the root
    events: [{ kind: "authored.set", node, field, value, impossible? }] }
  ```

  Facts are in the kernel's own fields and SI units (`name`, `orbit.semi_major_axis` in m, `orbit.eccentricity`, `body.mass` in kg, `body.radius` in m, `body.rotation_period` in s, `body.albedo`, `star.effective_temperature`, `star.luminosity` in W, belts' `body.radius_inner`/`body.radius_outer` and `belt.shape`). Derived values are left out. A body stamped IMPOSSIBLE carries `impossible: true` on its physical facts. The table of scene fields to kernel fields is `FIELDS` in `packages/ui-contract/src/clip.ts`.
- **Paste** (Build desk): Ctrl+V on the chart, or More › Paste (reads the clipboard; works on a phone). A dialog says what would land, what it would orbit and at what distance, at the ruler's time. A moon goes round the selected planet (or the planet of a selected moon); anything else goes round a selected star, else the primary. It names any pack the clip was made with that this campaign does not stack (or stacks at another version). At Engine depth it lists the new addresses.
- **Refusals in words:** on Explore, "Paste works on the Build desk. Press E to switch to Build."; on Run, only stock ships and stations (design 14.6, not built yet); a V3 clip (`sseClip: 1`) is recognised and waits for the V3 importer path (part 2); other text "does not hold a Star System Explorer clip"; a newer clip version says so.
- Copying and reading a paste write nothing: the state hash does not move.
- New lens tool `clip` ("Copy and paste bodies"): in Basic, Advanced and Building; Running has none.
- `sceneFromResolved` now also reads a body's `name` fact (after `v3.name`), so a pasted body keeps its name when a system is read back.

## Part 2 (done, 22 Nov): placing a paste, Undo, Redo and Cut

- Kernel ops used (kernel PR 134): `set_authored_batch {edits, occurred_at_s, evidence?, source?}`, `withdraw {address, at_s}`, `restore {address, at_s}`; all reply `authored`.
- Three new intents in `packages/ui-contract/src/intent.ts`, so they go through the seat rule and replicate like any other change:
  - `set_values {edits, at_yr, evidence?, source?}`: becomes `set_authored_batch`. Checked before the kernel: at least one edit, `u:` addresses, impossible and possible never mixed, catalogued needs a source and cannot be impossible.
  - `withdraw {address, at_yr}`, `restore {address, at_yr}`.
  - Only the GM applies them. A player seat that lists them is sent to the GM (never auto-approved). The shared approval fixture (`tests/fixtures/intents/decide-cases.json`, read by the kernel too) is unchanged.
- `placeBodies` and `withdrawBodies` in `packages/ui-contract/src/edit.ts`:
  - A paste sends the possible values as one batch and any impossible ones as a second, then puts one entry on the undo stack, field `presence` (`PRESENCE`), before `null`, after the top bodies' addresses.
  - Undo of a paste withdraws those top bodies (everything under them goes too); Redo restores them with every fact.
  - A cut is the reverse entry: Undo restores.
  - Both are refused while a what-if is open (a branch takes value edits only).
- `placeClip` now writes `orbit.host` (which the kernel's spec reads), not `parent`.
- Shell (`App.svelte`):
  - The paste dialog has **Paste here** (`[data-paste-place]`). It picks addresses with no history at all: a withdrawn address keeps its history, and facts set on it again stay hidden, so `placement` asks `history` and moves on to the next number.
  - The note says "Pasted …, orbiting …. Undo takes it back." and the root is selected.
  - **Cut** (`Ctrl+X`, a tool bar button and More › Cut): copies, then withdraws. It is offered only for bodies held in the universe (pasted ones). The sample campaign's own bodies come from its fixture file, so they cannot be cut yet; the note says so.
  - The campaign's own (fixture) system reads its pasted bodies back with `resolved_system` on every re-derive (about 15 ms; "unknown_system" while nothing is pasted) and sets them in beside the fixture's. They get the subtitle "Pasted · planet", the kernel's evidence stamps (no IMPORTED), and their host and orbit from their own facts, so a pasted star is never taken for the primary.
- Still to come: the pointer position on the chart setting the root's distance; V3 clips through the V3 importer; offering a missing pack to stack (the dialog names it); the credit chain on the authored events (`source`); Cut for the fixture's own bodies; players' screens showing pasted bodies (they read the fixture, and `resolved_system` is GM-only).
