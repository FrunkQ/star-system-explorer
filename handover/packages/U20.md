# U20: Copy and paste on the Build desk, part 1 (UI track)

Status: part 1 done 22 Nov 2026. Top-level design 8.2 ("Copy and paste, kept"), V3 parity row "cut, copy and paste anywhere". Part 1 is Copy and reading a paste. Part 2 places the paste in the campaign as one undo step, and waits on two kernel ops (below).

## What it does

- **Copy** (Build desk): the tool bar's Copy button, Ctrl+C on the chart, or More › Copy on a phone. It takes the selected body and everything that orbits it (by parent links, so a planet takes its moons; the star takes the whole system, but never the temperate zone, which follows from the star). The status line says what was copied and which values the physics will work out again where it lands.
- **The clip** is plain text on the clipboard: `sseClip: 2`, the envelope agreed with the Explorers thread (21 Nov), so the site can store and serve the bytes as they are.

  ```
  { sseClip: 2, generation: "v4",
    source: { site, title, url?, creditChain: [] },
    packs: [{ id, version }],            // the stack it was made under, bottom to top
    root: "n0",
    nodes: [{ id, kind, parent }],       // parents first; parent null for the root
    events: [{ kind: "authored.set", node, field, value, impossible? }] }
  ```

  Facts are in the kernel's own fields and SI units (`name`, `orbit.semi_major_axis` in m, `orbit.eccentricity`, `body.mass` in kg, `body.radius` in m, `body.rotation_period` in s, `body.albedo`, `star.effective_temperature`, `star.luminosity` in W, belts' `body.radius_inner`/`body.radius_outer` and `belt.shape`). Derived values are left out. A body stamped IMPOSSIBLE carries `impossible: true` on its physical facts. The table of scene fields to kernel fields is `FIELDS` in `packages/ui-contract/src/clip.ts`.
- **Paste** (Build desk): Ctrl+V on the chart, or More › Paste (reads the clipboard; works on a phone). A dialog says what would land, what it would orbit and at what distance, at the ruler's time. A moon goes round the selected planet (or the planet of a selected moon); anything else goes round a selected star, else the primary. It names any pack the clip was made with that this campaign does not stack (or stacks at another version). At Engine depth it lists the new addresses.
- **Refusals in words:** on Explore, "Paste works on the Build desk. Press E to switch to Build."; on Run, only stock ships and stations (design 14.6, not built yet); a V3 clip (`sseClip: 1`) is recognised and waits for the V3 importer path (part 2); other text "does not hold a Star System Explorer clip"; a newer clip version says so.
- Copying and reading a paste write nothing: the state hash does not move.
- New lens tool `clip` ("Copy and paste bodies"): in Basic, Advanced and Building; Running has none.
- `sceneFromResolved` now also reads a body's `name` fact (after `v3.name`), so a pasted body keeps its name when a system is read back.

## Part 2 (next)

- Kernel asks sent to "Build kernel resolve and rules" (22 Nov): (1) `set_authored_batch`, many edits at one time as one `authored.set` event; (2) a withdraw for Undo, so a pasted body and everything under it drop out of `scene`, `resolved_system` and `systems` from that time on, without deleting history.
- Then: Paste places `placeClip`'s edits (new addresses never in use: `body:N` under the system for a star's bodies, under the planet for moons; `belt:N`, `craft:N`) as one batch and one undo step; Cut is Copy plus withdraw; the pointer position on the chart sets the root's distance; the fixture system shows pasted bodies; V3 clips go through the V3 importer with its short report; a missing pack is offered to stack, or the values are stamped IMPOSSIBLE with "make physically sound" on offer; the credit chain is written on the authored events.
