# V1: view contract, scene descriptions, first player views (Chart, Card, Table, Text, Readout)

Status: done (18 Nov 2026), branch `claude/project-thread-adgixl`, on top of U3 and the kernel track's K9.

## What was built
- **One view contract for GM and player views** (`ui-contract/src/view.ts`): `ViewModule<S, C>`, generic over the scene description it draws and what its host gives it. GM views keep `ViewContext` (session, workspace). Player views get `PlayerContext`: parameters, the screen's vocabulary layer, a selection shared with the other views of the screen, and an optional `send(intent)`. They get no session and no workspace. Screen params gain a `list` type.
- **Player scene descriptions** (`ui-contract/src/player-scene.ts`): `PlayerScene` mirrors `sse_observe::Scene` field for field: audience, scope, and subjects with view, tags and facts. A fact has a value, a band or a placeholder, plus honesty marks. A vocabulary layer (`sse.vocab/0`, pack data) turns fields into labels, units, digits and sentences. Prefix entries (`orbit.*`) and unlisted fields still read. `describeFact` gives a value, a band ("270 to 290 K") or the placeholder, and never a guessed number. `checkPlayerScene` rejects malformed scenes and subjects outside the scope.
- **The first five views of the finite stack** (`packages/views/player-stack`, H8.2):
  - **Chart:** a log-radial orbital chart of the bodies whose orbit the audience has. Bodies known only to exist are listed as "Orbit: not known", never placed by guess. Phase angles are not player data, so bodies are spread by order. Keyboard: Tab and Enter.
  - **Card:** one subject's facts, with chosen fields first, placeholders kept, tags, marks, and moons as links.
  - **Table:** sortable columns named in the screen document, numeric sort on the value with unknowns last, and row selection.
  - **Text:** plain prose from the vocabulary's sentences. Unknowns are said plainly, and story fields are quoted.
  - **Readout:** one value as a number, a gauge, or a status light for a tag.
  - All five draw only with theme tokens (V2 adds the themes).
- **Player screen host** (`packages/shell/players.html`, `src/Players.svelte`): mounts the stack from `documents/players.screen.json` (layout grid, now with areas a to f) and `documents/vocab.plain.json`. A "Long range / Scanned" control stands in for the GM's Scanned button. V3 turns this host into the screens runtime.

## Scene source (kernel gap, reported)
K9 builds scenes natively (`sse-observe`), but the kernel message API has no scene op yet. I asked the coordinator for `scene {audience, scope, data_view?}` returning `sse_observe::Scene`, plus `scan_toggle` as a GM op; `subscribe` deltas can wait for V4.

Until then, the host fetches `scenes/tarn-before.json` and `tarn-after.json`. These are copied at build from `tests/fixtures/observe/` and are K9's verified outputs: sse-observe's tests assert the kernel builds exactly these. The page says so in its status line. Because the views take the exact Scene shape, wiring the op changes only the host.
