# V2: themes (tokens, frame parts, filter chains) and the six player themes

Status: done (18 Nov 2026), branch `claude/project-thread-adgixl`, on top of U5.

## What was built
- **Frame parts in the token schema** (`packages/skins/chart-room/src/schema.ts`). Views now say what each piece is and the theme decides how it looks. The parts are:
  - panel: ground, ink, muted
  - frame: line, width, radius, shadow
  - cap: the strip carrying a title, with ground, ink, rule, and an end block with width, colour and rounding
  - title: font, style, case, size
  - label: case, tracking
  - value: font, ink
  - unknown-fact style
  - row rule and its style
  - tag chip: ground, ink, radius
  - text glow
  - chart ground

  The new token type `keyword` carries its allowed values. Chart room and Night chart set every new token to their existing look, so the GM view is unchanged.
- **Theme documents** (`ThemeDoc`) gain:
  - `description`
  - `filters`, the filter chain
  - `vocab`, the vocabulary layer the theme brings
  - `palette`, offered to symbology's colour channel (V12)
- **Filter chains** (`packages/skins/player/src/filters.ts` and `chart-grammar/FilterChain.svelte`):
  - The steps are scanlines, glow, grain, vignette, tint and flicker. Each becomes a CSS overlay or a style on the screen container, so the browser composites them on the GPU. They never take a click and are hidden from screen readers.
  - Flicker is dropped under reduced motion. The whole chain is dropped for prefers-contrast: more, or when the viewer turns "Screen effects" off.
- **Six player themes** (`packages/skins/player/src/themes.ts`). All are original designs with generic names; none copies a franchise's artwork, fonts, colours or logos.

  | Theme | Look | Colours | Filters | Vocabulary |
  |---|---|---|---|---|
  | Chart | the chart room, offered to players | full | none | plain |
  | Paper | black on white for print, e-ink and handouts | 1 | none | plain |
  | Deck panels | dark deck, teal caps with an amber end block, condensed capitals, amber readings | full, with its own palette | none | plain |
  | Phosphor | green-screen terminal | 1 | glow, scanlines, vignette, flicker | plain |
  | Clean glass | bright white panels, soft depth, one blue | full | none | plain |
  | Field guide | warm paper, rounded letters, teal caps | full | grain | `vocab.guide.json` (friendlier labels and sentences) |
- **The five player views draw with frame parts** (Chart, Card, Table, Text, Readout). Their CSS names tokens only.
- **Player page:** a Theme picker over the six themes, remembered per device; a Screen effects switch shown for themes that have filters; and the theme's vocabulary (the views remount when it changes).

## Results (build-plan check: one screen renders correctly in all themes; no view contains theme-specific code)
- `tests/ui/theme-free.test.ts` scans every file under `packages/views` and finds no literal colour, no literal font, no theme name in script, and no theme check (`data-theme`). It also proves it catches each kind of leak. 0 leaks.
- `packages/skins/player/test/themes.test.ts` checks:
  - every theme resolves every token, and keywords stay within their options
  - text tokens reach 4.5:1 and line tokens 3:1 on their grounds in all six themes
  - a one-colour theme (Paper, Phosphor) uses at most one hue
  - filter chains map to overlays, with reduced motion, effects off, clamping and a bad tint covered
- Browser (`tests/ui/themes.e2e.mjs`, chromium here; CI runs chromium and firefox): for each theme at 1440 px and 390 px:
  - the card's computed panel fill, frame radius, cap fill and title case equal the theme's tokens
  - the same facts are shown
  - there is no sideways scroll and no page errors

  Field guide labels mass "Heft". Phosphor draws scanlines, vignette and flicker; the effects switch removes them; reduced motion drops the flicker. Screenshots are in `V2-screens/`.
- Earlier e2e suites still pass (shell, players, setup). svelte-check reports 0 errors and 0 warnings; 43 UI node tests pass.

## Notes for later packages
- **Vocabulary precedence.** Screen documents name only plain, physics or story, so on the player page the theme's vocabulary wins and the screen's is the fallback. V3, the screens runtime, should settle the rule in the screen schema.
- **Fonts.** Themes name font stacks with system fallbacks; no web fonts are loaded yet. A presentation pack can bring its fonts with its licence later.
- **Packs.** Themes are TypeScript documents for now. Moving them into a presentation pack (`provides.other.themes`) is a data move: the documents are already plain JSON-shaped.
