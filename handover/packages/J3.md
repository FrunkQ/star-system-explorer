# J3: boxes, blocks made of blocks

Status: done (19 Nov 2026). Kernel track, PR into `main`. Design: `handover/design/SSE4-record-logic-programs-design.md` (track J) section 4, section 10 row J3.

## What was built
**Box documents (`sse-flow::boxes`).**
- `BoxDoc` (`format: "sse.box/1"`) has:
  - `id` and `version`;
  - `inputs` (as flow inputs) and `outputs` (`name`, `from` an inner `node.port`, or `in.<name>` to pass an input straight through);
  - `nodes` and `wires`;
  - `promoted_params` (`name`, `node`, `param`);
  - `explain`, `references` and `tests` (golden cases keyed by output name);
  - `fictional`.
- `NodeDoc.box: "id@range"` uses one. The range is a semver range on the box's version and defaults to any.
- **Inlining.** `Flow::compile_with(doc, cx, boxes)` flattens every box, then compiles as usual.
  - Inner nodes take ids `<box node>/<inner node>` (`star/photo/teff`). Results, validity, work units and explain traces are those of the hand-wired flow.
  - A flow without boxes inlines to itself, with the same document and hash.
  - `Flow::boxes` lists each use (prefix, id, version, depth, fictional) so the editor can show a box collapsed, with a way in.
- **Readable errors:**
  - a self-containing box, with the chain (`box t.a contains itself: t.a > t.b > t.c > t.a`);
  - nesting past `MAX_DEPTH` (8), with the chain;
  - a missing box, or a version outside the range asked for;
  - an unknown promoted parameter, an unwired or unknown box input, or an unknown output.
  - An error inside a box is reported once, not again at every level above it.
  - Plain `Flow::compile` refuses a box node and says to inline first.
- **A box's face** (`box_decl`) is an atom declaration:
  - inputs with dimensions and validity (the intersection of every inner port the input feeds);
  - outputs with their dimensions;
  - promoted params with the inner declaration's default and range;
  - cost class (the maximum), references (the union) and the box's explain;
  - class `logic` when everything inside is logic.
- `run_box_tests` runs a box's own cases. `compile_box` compiles a box on its own.

**Packs (`sse-pack`).**
- `provides.boxes`, skipped when empty, so every existing pack hash is unchanged.
- Boxes and flows share one id namespace. Providing an id again without `replaces` is refused.
- `replaces: {flow: <box id>, pack, range}` overrides a lower pack's box, with the same rules as for flows.
- `ResolvedStack.boxes` and `box_packs`.
- A fictional box, or a box from a fictional pack, marks whatever a flow using it publishes as fictional, at any depth.

**Kernel.** `load_stack` runs each box's golden cases, then compiles every flow with the stack's boxes inlined. A failing box case refuses the stack, naming the box and the case.

**Logic (`sse-logic`).** `Condition::into_box`: a K8 rule written as blocks becomes a box with one output, `holds`, that any flow, box or program can use.

## Checks
- `sse-flow::box_tests` (3 tests):
  - **Twin.** The toy star-and-planet flow, boxed as `toy.star` (with `toy.photosphere` nested inside and a pass-through output) and `toy.bulk`, equals the hand-wired twin:
    - the same nodes, params, wires and publishes;
    - every published value, validity and work count across four stars;
    - every step of every explain trace, except the flow hash, which covers the wires in their written order;
    - the flow's own golden case passes;
    - a promoted parameter reaches its inner node.
  - **Refusals.** Self-containing boxes are refused directly and through three levels. Exactly 8 deep compiles and 9 deep is refused, both with the chain. The other refusals are each named.
  - **Face.** The declaration's dimensions, validity intersection, promoted param, cost maximum, reference union and explain are checked. The box's golden case passes, and a wrong one is reported by name.
- `sse-pack::a_pack_replaces_a_box_explicitly`:
  - a duplicate box without `replaces` is refused;
  - with `replaces`, the rival's box is used, and its fictional flag reaches the published kinds;
  - a wrong base version is refused;
  - a box version outside the flow's range is a compile error naming both.
- Kernel `boxes_load_with_the_stack`: a stack with boxes loads, and a failing box case refuses it.
- `sse-logic::a_rule_as_a_box_is_the_rule`: the habitable rule as a box, used twice (once negated), gives K8's answer and evidence on the 720-subject grid, entering and staying.
- Every existing flow, golden, pack and contract hash is unchanged.
- `scripts/check.sh` passes.
- JS contract: 147 of 147 through the Web Worker.
- Harness: Node and Chromium identical to native.
- UI tests: 131 pass.

New fixtures: `tests/fixtures/boxes/toy-boxes.json` (three boxes) and `toy-boxed.json` (the toy flow using them). No golden changed.

## Limits
- `map through a box` (a list block that runs a box per element) is not built. It needs a box evaluated as a unit, not inlined, and comes with programs (J6) if they need it.
- `Explanation` shows inner ids (`star/lum`). The collapsed view is for the UI, from `Flow::boxes`.
- The kernel does not yet list boxes in `atoms`. The flow editor gets a box's face from `box_decl` once the UI asks for it: add a `boxes` op then.
- A box replaced by a pack keeps its id, so flows asking `^1` take any 1.x replacement. A replacement with a new major version breaks those flows with a readable error, on purpose.
