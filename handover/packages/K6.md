# K6: kernel message API, worker binding, typed client, cancellation, progress, cost classes, tiers

Status: done (18 Nov 2026).

## What was built
- Crate `sse-kernel`: the `sse.kernel/1` request/response protocol (17 ops) and `Kernel::handle_json`, tying packs, flows, chronicle, branches and draws together. Every op declares a cost class and its edge behaviour (`ops()`); capability tiers are defined once (`tiers()`).
- `sse-wasm` exports `Kernel` (JSON in, JSON out).
- `packages/contracts`: TypeScript protocol types generated from the Rust types by ts-rs (`cargo test` writes them; CI fails if they are stale).
- `packages/kernel-client`: a worker entry that runs in a browser module worker and a Node worker thread, and `KernelClient` with typed calls, long jobs in budgeted steps with progress in work units and cancellation (AbortSignal), `measure()` for the device's capability tier, and `can(cost)` returning the edge with a reason.
- The cross-device page now also runs the full contract through a real Web Worker and shows the device's measured tier.

## Design sections implemented
H9.1 (the subset that exists by M1: load_stack, open_universe, set_authored, history, state_hash, derive, explain, draw, branch/commit/discard, jobs), build plan section 2 (cost classes, tiers, edges). Not yet: resolve, subscribe, query_feasible, plan_route, sift, export/import (their engines arrive in K7 to K9, T3, P3).

Choices:
- Requests carry `op`, responses `type`; errors are responses (`{"type":"error","code",...}`), never exceptions across the boundary.
- Long work runs as jobs stepped by the worker with a unit budget; the worker yields between steps, which is where cancel lands. The kernel never reads a clock; the client times the benchmark job.
- Tiers: basic (any; runs up to light), standard (>= 200k units/s; medium), capable (>= 2M units/s; heavy). A unit is one fixed 12-step Kepler solve. Thresholds are first guesses to calibrate on real phones (H12 experiment 7).
- Kernel atoms are the toy registry until P1 brings the physics library.

## Commands
```
cargo test -p sse-kernel                 # native contract against tests/golden/contract.jsonl (SSE_BLESS=1 rewrites)
scripts/build-harness.sh && npm test     # same requests through a Node worker thread
node tests/harness/run-browsers.mjs      # same through a browser Web Worker
```

## Results
- 41 contract requests cover all 17 ops (a test fails if an op has no case), including error paths: derive before a stack, a rejected stack (one-publisher), a bad stream name, an address outside the universe, an unknown branch after commit, a finished job, a cancelled job, a zero-unit job, an unknown op.
- Native, Node worker thread and Chromium Web Worker give byte-identical responses (41 of 41). CI adds Firefox and WebKit.
- Behaviour checks: fictional values flagged; branch then discard leaves the state hash unchanged and commit changes it; a 50,000-unit job reports progress at 10,000-unit steps; a 10-million-unit job cancels after three steps; a simulated weak device is refused heavy work with the reason and the GM fallback.
- Local Chromium measured about 1.9 million units/s (tier standard).

## Golden hashes
Added `tests/golden/contract.jsonl` (41 responses). Harness digests unchanged.

## Known limits
- Release wasm is about 1.2 MB before compression and without wasm-opt; size work belongs with X1.
- One kernel per worker, single-threaded; the optional worker pool (H3) waits for resolve.
