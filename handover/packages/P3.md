# P3: V3 importer (one-way)

Status: built, tested on a synthetic fixture, and run on three real V3 saves on Alex's PC (18 Nov 2026; see
"Real-save check" below). One difference is still open (Procyon e Ring mean motion). The saves stay outside the repo.

## What was built
- Crate `sse-import-v3`: `import_json(text, universe_id)` reads a V3.1 `starmap.json` or `system.json` and returns
  authored facts by V4 address, chronicle events, and a report (`sse.v3-import-report/1`).
  - Addresses: `u:<id>/sys:@n/body:@n`, `bary:@n`, `craft:@n`, in V3 file order. Parents and orbit hosts become
    address-valued facts (`parent`, `orbit.host`), resolved in any order.
  - Authored quantities in SI under V4 kind names: `body.mass`, `body.radius` (and inner, outer), `body.rotation_period`,
    `body.axial_tilt`, `body.obliquity`, `star.effective_temperature` (stars only), `system.age`, the six Kepler
    elements as `orbit.*` in metres and radians. Everything else authored is kept raw as `v3.<field>` until a later
    package maps it (makeup, atmosphere, hydrosphere, construct records and so on).
  - Derived V3 fields are never imported. Recomputed with `sse-atoms` and reported as differences: density,
    surface gravity, `orbit.hostMu`, `orbit.n_rad_per_s`. All other derived fields are counted by name under
    `derived_not_compared`, so the report says what has no V4 atom yet.
  - Tags: physics, rule and derived tags are dropped (V4 re-emits them) unless they carry V3's `override`; manual,
    authored and inherited tags are kept with `secret` and `disclosure` intact.
  - V3 `overrides` and `anomalies` become `authored-impossible` facts and the address is listed under
    `honesty_marks`.
  - Unknown fields are kept as authored and listed under `unclassified`: nothing is lost silently.
  - Field tables in `src/classify.rs`, from `docs/v3-save-fields.md`.
- `sse import-v3 <file> [universe-id]` in `sse-cli`: report JSON to stdout, a one-line summary to stderr.
- Fixture `tests/fixtures/v3/synthetic-sol.json`: hand-written from V3.1's `types.ts`, labelled as not a real save.

## Checks (`cargo test -p sse-import-v3`)
- Counts, addresses, parent and host links; SI conversion of authored quantities.
- Derived values recomputed: Earth's density, gravity, host GM and mean motion within tolerance; the Moon's
  overridden V3 density is flagged as outside tolerance with V4's 3.344 g/cm³, and carries an honesty mark.
- Physics tags dropped, manual and overriding tags kept with `secret`; GM notes kept.
- Unknown, presentation and dropped fields all reported; no warnings on the fixture.
- Same file gives the same report and chronicle state hash; one authored edit changes the hash.
- Bare `system.json` imports; non-saves and a non-integer `bundleFormat` are refused.

## Not yet
- `.sse.zip`: unpack first (the CLI says so). A zip reader adds a dependency; add it when the real-save run needs it.
- Catalogued evidence: V3 marks real-sky bodies by tags and `figureSources`; the importer labels everything
  authored until the real saves show which marker to trust.
- V3 `albedo`, `equilibriumTempK` and the climate chain: V3 derives albedo from composition, and V4 has no albedo atom
  yet, so these are reported as not compared. P4 and P5 close this.
- The kernel has no `import` op yet (H9.1 lists export/import): the integration step wires `Import::events()` into
  `Kernel`. Not done here to keep out of the kernel crate.

## How to run the real-save check
```
cargo run -p sse-cli -- import-v3 <path to starmap.json> v3-<name> > report.json
```
Pass when: no warnings, every row in `differences` with `within: false` is explained in the run's notes (an override,
a V3 fault, or a V4 model limit), and `unclassified` is empty or each entry is added to `src/classify.rs`.

Differences outside tolerance:
- Lunar Gateway `orbit.hostMu`: V3 4902.8 against V4 4.9003e12. V3 stored the Moon's GM in km³/s²; V3's own
  orbit code (`orbits.ts`) takes m³/s². A V3 data slip; V4 recomputes it. The importer now names this in `via`.
- Procyon e Ring `orbit.n_rad_per_s`: V3 4.9455e-4 against V4 4.7303e-4 (4.4 percent). **Open.** V3 reads mean
  motion from its stored `hostMu`, so V3 likely used a larger host mass (planet plus moons, or a barycentre).
  Needs the ring's `hostMu` and host `massKg` from the save to settle.
