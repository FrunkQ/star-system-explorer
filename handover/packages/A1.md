## What was built
- **`packages/agents/src/agents.ts`**, written fresh in the shape `docs/ovid-agents.md` describes:
  - **Providers**: the same three kinds as Ovid (OpenRouter with one key; LM Studio and Ollama on this computer), plus "another provider" by its `/v1` address. All are spoken to through the OpenAI-compatible `/models` and `/chat/completions`.
  - **Jobs**: Support (Tars), Building (Orac), Describing (Minerva) and Deciding (cheap checks). Each job links one provider and model.
  - **Picks**: `picks.json` ships with every job "not measured yet". No model is recommended without a measurement.
  - **Ledger**: before every run the panel shows an estimate (tokens in, maximum out, price when the provider lists one). After the run it shows the real tokens and cost. There is a daily cap, and a run that would pass it is refused before sending.
  - **Context guard** (Ovid's loaded-context rule): a prompt that would not fit the model's context is refused before sending.
- **Keys** live in this browser only (`localStorage["sse4.agents"]`). They are sent only to their own provider, in the Authorization header. No peer-to-peer, share, players' or session module imports the agents (test), so a key cannot reach another device or a state hash.
- **Panel** (`AgentsPanel.svelte`, from "Agents" on the chart room's status line), with four tabs:
  - **Link models**: add, check (lists the provider's models) or remove providers; link each job; set the cap; see today's runs and spend.
  - **Tars**: works now. Ask a question about SSE or the selected body, with a humour setting.
    - Tars is told he is read-only, never computes physics, and must say where every number came from.
    - He is given only the chart's facts for the selected body.
  - **Orac**: shows its link, and says the change-request loop comes with A2 (on Ovid's loop).
  - **Minerva**: shows its link, and says narrative comes with A3, after the story finder.
- With no key, every agent says it is not linked and the app works as before.

## Part 2: reconciled with Ovid Next's source (19 Nov 2026, agents track)
Ovid's source was read on Alex's PC (`C:\Development\ovid-next`, read only): `browser/src/models/links.ts`, `ledger.ts`,
`loaded-context.ts`, `estimate.ts`, `wires.ts`, `agent/builder.ts` (Metamorphosis, the builder loop), `play/support-ask.ts`
and `support-report.ts` (tech support), `LICENSING.md`.

### What changed
- **Keys apart from the settings** (Ovid's `saveLinks` writes the link list without keys). Settings stay in `sse4.agents`;
  each provider's key has its own entry `sse4.agents.key.<provider>`. A part 1 key inside the settings is moved on first
  read. A removed provider's key is deleted with it. `loadAgents`, `saveAgents`, `memoryStore` in `agents.ts`.
- **Keys out of anything sent** (Ovid's `clean`): every message is cleaned before sending, by the value of every stored key
  and by key shape (`sk-or-`, `sk-ant-`, `sk-`, `Bearer`, GitHub tokens). Ovid's catch-all "any 32 base-64 characters"
  shape is not used: SSE's text carries state hashes that look like that.
- **Addresses mended** (`normalBase`): scheme added, `/v1` added when no path is given, a pasted endpoint taken off.
- **Listed prices** (`listedPrice`): a negative price is "varies" and gives no estimate, never a price.
- **Loaded context** (`fromLmStudioV1`, `fromOllamaPs`, `readLoaded`, `contextOf`): a local model plans with what it is
  loaded with, read from LM Studio's `/api/v1/models` or Ollama's `/api/ps` when its job is linked; 4096 when the server
  does not say; never the listed maximum. A refusal says to load the model with a longer context.
- **Ledger**: failed calls are kept (`ok: false`), each row has its time taken, and money nobody reported stays unknown
  ("and N with no price given"), never zero.
- **Replies** (`readJson`, `readLookup` from Ovid's `readReply` and `readLookup`): JSON in a fence or bare; a lookup
  (`need`, `find`) is told apart from an answer. A2 to A4 use these.
- `NOTICE` names the lifted parts and the relicensing; each lifted function names its Ovid file and function.

### What was deliberately not lifted
- Ovid's household server, lent keys, paired devices and "keys move to the main PC": SSE4 has no home server, and a
  player device never calls a provider at all (docs/ovid-agents.md section 2).
- Drawing, filming, voices, embeddings and Ovid's own model server: not asked for.
- Ovid's fallback chain (a job with no model follows Writing): SSE4's jobs stand alone, so an expensive model is never
  used for a job it was not linked to.
