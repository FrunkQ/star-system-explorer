# V11: Orac-first configuration (style and settings documents)

Status: done (18 Nov 2026), branch `claude/project-thread-adgixl`, on top of V3.

## What was built (H8.9)
- **Parameter schemas, richer** (`ui-contract/src/view.ts` `ParamSpec`). Each setting has a name, type, range or options, default, unit and a one-line meaning, plus three new fields:
  - `group`: content, look or behaviour.
  - `cost`: the cost class when the setting is engaged. A yes/no costs when it is on, a number when it is above its default, text when it is not the default.
  - `cost_options`: a cost for each option of an enum.
- **Style documents** (`ui-contract/src/style.ts`, `sse.style/1`):
  - Each is `{id, name, description, view, extends?, settings, promote?}`.
  - `resolveStyle` follows `extends`, base first. It refuses loops, missing bases, and bases written for another view.
  - `checkStyle` checks the whole chain against the view's schema: unknown settings, wrong types, out-of-range values, promotes of settings the view lacks, and **cost against a device tier**. The tier table (basic up to light, standard up to medium, capable up to heavy) is the kernel's. A test reads `crates/sse-kernel/src/protocol.rs` so the two cannot drift.
  - `promotedOf` returns the controls people get: the style's own `promote` list, else the view's promoted settings.
  - `settingsDiff` returns a change as a reviewable list.
- **Screens name styles.** A screen item can carry `style`, and its own `params` go on top. `checkScreen` takes the style registry and the device tier, and applies the same budget check to plain items too.
- **Every shipped view has a described schema.** Player views gained real, wired settings, and their schemas now live in `player-stack/src/schemas.ts` so tools and tests can read them without a renderer:
  - Chart, 7 settings: names on or off, name size, mark scale, scale note, unplaced list, **animate** (costs medium).
  - Card, 7 settings: only the listed fields, tags, moons, view caption, density.
  - Table, 7 settings: first sort, sortable, row limit, empty-cell text.
  - Text, 4 settings: sentence limit, heading, story quotes, size.
  - Readout, 6 settings.

  GM views gained settings where they had few: change requests show closed; the time ruler shows edits; Symbols shows previews. Each view promotes at most five settings.
- **Promoted controls render from the schema** (`chart-grammar/Settings.svelte`): a toggle for a yes/no, a slider with a readout for a ranged number, a picker for an enum, a box for text or a list. Each control shows its meaning and its cost.
- **Styles screen** (GM header "Styles", `packages/views/styles`):
  - The list of every GM and player view, with counts of settings and promoted settings.
  - The selected view's whole schema, the list Orac works from, with promoted settings marked.
  - The view's styles. You can start a new style from one (it `extends` it), edit it with the promoted controls or as the raw document, and check it for a basic, standard or capable device (defaults to this device's measured tier). The change from the base shows as a diff.
  - Keep on this device (`shell/src/styles.svelte.ts`), and Put back.
  - A preview of player views through the screens runtime, on the live scene.
- **Shipped styles** (`shell/src/documents/styles.json`):
  - Plain chart.
  - Across the table: extends Plain chart with bigger names and marks.
  - Orrery: extends Plain chart, animated, and promotes its own three settings.
  - Brief card.
  - Teaser text.
  - Top-five table.
- **Composer**: each item has a Style picker and a Settings panel of its promoted controls, both drawn from the schema. Styles are checked for this device's tier.
- **Players page**: resolves item styles from the shipped and kept styles, checked for its own measured tier.
