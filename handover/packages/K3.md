# K3: chronicle, stores, checkpoints, branches, run manifest

Status: done (18 Nov 2026).

## What was built
Crate `sse-chronicle`: content-hashed events with the three distinct times, an append-only chronicle with a hash chain, generic fact folding, checkpoints that refuse to be used when stale, branches (look-ahead) with discard and commit, authored/resolved store views, a derived cache, and the run manifest. `sse_core::cbor::Value` is now serde-capable so payloads carry arbitrary canonical data.

## Design sections implemented
H5.4, H5.5, H5.6, and the branch half of H6.3. Choices the design left open:
- `UniverseTime` is integer seconds plus nanoseconds (exact ordering; about 290 Gyr of range).
- Fold order is `(activated_at, recognised_at, id)` (`sse.order.v1`, in the manifest). `recognised_at` only breaks ties between events activating at the same instant; it never changes a value otherwise.
- Payload convention: `set[address][field]` and `unset[address]`; anything else goes in `data`, carried and hashed but ignored by the generic fold (suites fold their own).
- A checkpoint records how many events it covers and the chain head; it is refused if the chronicle diverged, if its stored hash does not match, or if a later event activates before the checkpoint time.
- Commit re-stamps branch events onto the main chronicle (their ids change because `recognised_at` does; causes are remapped) and appends one `commit.branch` event caused by them.
- One-publisher-per-quantity (H5.5) is a pack-stack rule, so it is enforced in K5, not here.

## Commands

## Results
- Property tests: fold of all events equals checkpoint plus later events, for random edit scripts and random cut times; branch then discard leaves the state hash and chronicle head unchanged; state hash independent of map insertion order.
- Unit tests: duplicate, unknown cause and non-increasing stamp rejected; activation order beats append order; stale checkpoint refused; commit makes main equal to the branch's look-ahead; manifest round-trips through canonical CBOR and JSON with the same id.
- Golden: a fixed 200-event script gives state hash `08a0bc87…314443` (`tests::golden_state_hash`).

## Known limits
- Branches live in memory on the chronicle; persisting them is a K6/U4 concern.
- The fold is a full re-fold (checkpoints make it incremental). Per-address indexing for speed waits until resolve volume needs it.
