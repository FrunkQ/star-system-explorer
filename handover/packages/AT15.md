# AT15: wearing a kit (atlas design 11A.3, 11A.4 rule 5)

## Part 1 (25 Nov): control sets, one shared drawing, and the kit's screens

- **Control sets as data.** `ui-contract/src/atlas/controlset.ts`. A part declares a control as a kind: button,
  switch, choice, step, dial, tab or link (AT13). A control set says how each kind is drawn in a look:
  - `frame`: plain, bracket, pill, cap, ink or key.
  - `case`: as-written or upper.
  - `hotkey`: the key marked inside the word, as in `[P]RINT`.
  - `lit`: fill, invert, glow, underline or bold. This is how the control shows it is on, chosen or pressed.
- **Shipped sets.**
  - `plain`, the root: the chart room's own buttons.
  - `hauler`: brackets, capitals and keys, inverted when lit. Print reads `[P]RINT`.
  - `corporate`: glass pills that glow.
  - `deck`: console caps in capitals.
  - `guide`: gadget keys, with tabs and links inked.
- **Inheritance.** A set leaving a kind out takes its `extends` parent's drawing, then plain's, so a variant costs
  nothing.
- **Functions.** `drawingOf(set, kind)`, `controlWords(words, drawing, key)` and `checkControlSet(doc)`, which returns
  sentences, as the kit loader does.
- **Kits name their set.** `sse.kit/1` gains `control_set`: a set by id, or a set of the kit's own, which
  `checkKit` checks. The four starters name hauler, corporate, deck and guide. `controlSetOf(kit)` resolves it.
- **One shared drawing:** `chart-grammar/src/KitControl.svelte`, a new file agreed with the coordinator.
  - It draws any declared control in any set, in the look's tokens only.
  - Minimums no set can go under: a 44 px press target on touch (32 px with a mouse), the focus ring, and no motion
    under reduced motion.
  - Switches, choices and tabs carry `aria-pressed`. A set showing keys gets `aria-keyshortcuts`.
- **The Atlas part wears it.** With `ctx.control_set` set (a players' screen wearing a kit), its Contents, Back,
  Next and Print are KitControls. A set that shows keys answers P, C, N and B. Without it, the GM's chart room keeps
  the Atlas's own buttons.
- **`kitScreen(kit, situation)`** turns a kit's layout for a situation (after `extends`) into an ordinary
  `sse.screen/1` document, for the Run desk thread's players' screen. It returns null when there are no boxes: a
  holding card, or an unknown kit.
- **Agreed with the Run desk thread.**
  - The role card gets `Seat.kit` (a KitDoc id) and `Seat.palette`, travelling with the seat plan like the brand.
  - Precedence: a role's own Switchboard layout, then `kitScreen(kit, situation)`, then the Bridge.
  - The players' screen puts the resolved set on each part as `ctx.control_set`.
