# K10: suite socket and coordinator at time boundaries

Status: done (18 Nov 2026). Track "kernel resolve and rules", branch `claude/project-thread-dzkz4p`.

## What was built
New crate `sse-suite`: the `SuiteAdapter` socket (manifest, requirement profile, determinism class, `provide`, `advance`, checkpoint and restore, explain), a `Physics` provider trait for the authoritative physics at boundaries, the L0 `NullSuite` ("no life model installed"), and the `Coordinator` that steps common time boundaries, hands each suite pinned, content-hashed inputs, checks what comes back against the suite's declared rights, and commits everything to the chronicle in a fixed order so the chronicle alone replays the run.

## Design sections implemented
H11 (suite socket, coordinator, ownership: "a life suite may change an atmosphere; it may not override pressure"), the interface half of H11A stage L0, and H9.2 determinism classes. Choices the design left open:
- **Boundary order**: boundaries every `step_s` seconds, the last landing exactly on the target time. At each boundary: physics steps first (an `evolve.transition` event), then suites in id order, each seeing the physical state at the boundary plus what earlier suites committed.
- **Domain**: a suite is handed every address in the coordinator's scope that has all its required fields; the `InputDataset` (address, interval, required values, the suite's own fields) is content-hashed and the hashes go on the record.
- **Rights**: a suite sets only the fields it `owns` and sends additive fluxes only into fields listed in `may_flux`. Anything else (setting temperature, a flux into pressure, writing outside scope, a non-finite flux) is dropped and reported as a violation, both in the run report and in the boundary event. Never applied, never silent.
- **Commit**: one `suite.<id>.advance` event per suite per boundary, setting owned fields, flux results as absolute values, and signatures as `signature.<suite>.<name>` (ready for data views: a biosignature at Scanned). It cites the suite's previous boundary event and that boundary's physics event; its `data` holds the class, input hashes, the suite's checkpoint, violations and suite version. Suite events follow as `suite.<id>.<kind>`, citing the advance.
- **Resume** reads each suite's checkpoint from its last advance event, so a run can stop and continue from the chronicle alone.
- **Class B** suites run the same way on the GM machine; other devices never run them and fold the recorded events (`replay_state`).

## Results
- Acceptance, fluxes exchanged: three worlds over 5 Gyr in 20 boundaries with a brightening star. A stub life suite (logistic biomass that needs liquid water, an origin drawn once per world from keyed draws) sends oxygen fluxes; stub physics cools a world by its oxygen at the next step. Living worlds end with oxygen, a biosignature, an origin date and a temperature below the lifeless track; the frozen world stays lifeless with no oxygen. Each boundary event cites the previous boundary and the physics step.
- Acceptance, bit-identical replay: two full runs give identical reports and chronicle heads; stopping at 2 Gyr and resuming with a fresh coordinator from the chronicle gives the same head and state hash as one run; a class B run copied event by event to a chronicle with no suite gives the same state hash at all 21 boundary times.
- Rights: a rogue suite's pressure flux and its attempt to set temperature are both dropped (pressure stays 1e5 Pa, temperature never 999 K) and reported with reasons, in the report and on the record.
- A second suite with the same id is refused; a zero step is refused; the null life suite runs and explains "no life model installed".

## Cost classes and edges
`sse_suite::ops()`: advancing is medium (as the suite declares; class B only on the GM machine), replay is light on any device.

## Known limits
- Not yet reachable through the kernel message API: suites are installed in code, and the first real suites (life L0/L1, cosmos G) will choose how they are exposed. `branch` already gives look-ahead runs a home (K3).
- The physics provider here is a trait; T1 (epoch stepping) is its first real implementation.
- Fluxes are additive deltas on scalar fields; vector or profile fluxes wait for a suite that needs them.
