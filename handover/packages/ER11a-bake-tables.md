# ER11a: the kernel bakes tables for the renderer (`sse.table/1` and `bake`)

Track ER (edits that reach everything). Design: `handover/design/SSE4-edits-reach-design.md` section 11 ("the kernel bakes tables; the renderer keeps only geometry and lookups") and section 12 (ER11a). Built 26 Nov 2026 on PR 618 (XO2, XO3) and PR 630 (XO4); the XO4 thread handed the picture's conversion to this package.

## What landed

- **The format, `sse_physics::table`.** A `Table` has: `format: "sse.table/1"`, `id`, `subject` (as asked), `size` (`small`, `medium`, `large`) and the `tier` asked; `axes` (name, unit, `even` or `log` spacing, first and last node, node count, what a reader computes to index it); `channels` (name, unit, `from`: a block id or a compiled function); `values`, one flat array of 32-bit floats, **channel fastest, then the first axis, then the second**; `hash` (keys the renderer's texture); `physics` (the physics hash it was baked under); `reads` (blocks and compiled functions it read, with block versions); `rests_on` (empty until ER8 marks results from the door); `sampling`; `why`; `stand_ins`.
- **Sizes by tier.** `Size::of_tier`: `still`, `gpu-ultra`, `capable` take the large size; `gpu-high`, `standard` (and none) the medium; everything else (`gpu-basic`, `canvas`, `text`, `basic`) the small. The renderer's drawing tiers and the device's measured tier (`ctx.styles.tier()`) both work.
- **Sampling, the one allowed approximation.** `Table::sample` is a linear read in each axis between the nodes (what a GPU's four-texel mix does). `Table::seal` fills the nodes from the producer's exact function and then runs `check_sampling` (the sampling test helper): probes a quarter and half way between nodes, worst error per channel, relative to the exact value or against a stated floor where the exact value is smaller. A table publishes `sampling.worst` beside `sampling.bound` and `within`. One fudge-register row for the class (`docs/fudges.md`, "table sampling").
- **The op, `bake`.** `{ op: "bake", table, subject?, tier? }` → `{ type: "baked", table, kept }`. Kept by id, subject (canonical JSON), size and physics hash, newest 24 (`crates/sse-kernel/src/bake.rs`); a new stack is a new physics hash, so a new table. An unknown id lists the known tables. `Session.bake` in ui-contract; `bake` is in the "Light, spectra and the sky" perf chunk.
- **The renderer's reader, `packages/ui-contract/src/table.ts`.** `indexOf`, `nodeAt`, `sampleTable` (the same read as the kernel's), `channelOf` (throws on a renamed channel), `texelOf` (texture coordinates with texel centres on nodes), `rgbaOf` (the values as an RGBA float texture, first axis across).
- **The first table, `sse.light.disc`** (`crates/sse-light/src/disc_table.rs`). Subject: `gravitational_radius_m` (or `mass_kg`) and either `rate_kg_s`, `inner_m`, `outer_m` or the hole's `feed` as `read_light_paths` gives it (the kernel takes the edges and `Feed::disc_rate_kg_s` from it). Axes: `r` in gravitational radii, log, inner edge to outer edge; `lambda_over_r`, even, ± 1/√(1 − 2/r_in), the photon's angular momentum about the disc's axis b sin i sin α over r (a photon leaving r for a far viewer has b ≤ r/√(1 − 2r_g/r)). Channels: `shift` from the block in force `sse.light.disc_shift` (run at b = |λ|, i = π/2, α = ±π/2), and `t4`, the ring's T⁴ from `sse_light::disc_temperature` (T⁴ because T rises from zero as (r − r_in)^¼, which no linear read follows). No rebake when the viewer drags the tilt. Nodes: 384 × 17, 1024 × 33, 2048 × 65.
- **The picture reads it.** `light-path.ts`: `discShift`, `discTemperature`, `discTScale` are gone; `discSubject(p)` is what to bake, `discOf(table)` the disc, `discAt` one read; `traceRay`, `brightest` and so the exposure all go through it. `gpu-light-path.ts`: the disc table is an RGBA float texture read at four texels and mixed, as the kernel samples. `BlackHole.svelte` bakes on choosing a hole, with the device's tier, and draws a fed hole only once its table is in.

## Checks

- `sse-physics` table tests: nodes exact, linear axes exact between nodes, sampling goes red on a coarse table and green on a fine one, tiers pick sizes, bad axes and non-finite values refused.
- `sse-light` `disc_table_tests`: every fixture within its bound at every size; the kernel's own traced points (XO3's brightest, approaching and receding) read back with their shift and temperature within the bound; **editing `sse.light.disc_shift` changes the table** (the gravitational redshift taken out of a copy of the block: the shift channel follows it exactly, T⁴ does not move); a block that reads the tilt other than through b sin i sin α is named in `stand_ins` (the bake checks its own indexing at four probe points); a feed gives the same table as its numbers; a disc inside 2 r_g is refused. **Seen red:** with the producer reading the shipped library instead of the blocks it is handed, the edit test and the indexing test fail.
- `sse-kernel` `bake_tests`: baked, kept on a second ask, sized by tier, a new physics bakes afresh, unknown table and bad subject say what is baked.
- `packages/ui-contract/test/table.test.ts`, through a real kernel: the reader gives the traced points their shift and temperature within the bound; nodes read back exactly; texel centres on nodes; a phone's tier gets the small size.
- `packages/renderer/test/light-path.test.ts`: the block's worked examples read off a baked table within its bound; the picture's rays at the kernel's traced points within the bound (was 1e-9 against the copied law). The starved hole's dimming figure is held to 2% (was 1%; it reads 1.1%): at 800 K the visible band is deep in Planck's tail, where light goes as about the 30th power of temperature, so the table's read of temperature is magnified.
- `tests/ui/black-hole.e2e.mjs` passes unchanged (shadow and arch within 2 px, approaching side brighter, every band and Composite, the quasar's ultraviolet peak, the starved centre dark). Screens before and after differ only in the sky chip and a few stars (timing), not in the disc; screens in project files `sse4/handover-screens/ER11a-screens/`.
- No golden moved: `bake` is a new op with no contract case. The side-door ledger takes no new line from this package.

## Until later packages

- **Edits reach the table once blocks come from the stack (ER3).** The table is built from the blocks the physics in force hands over, so it follows the block in force; until ER3, the block in force is always the shipped one, so the edit test builds an edited block directly.
- `rests_on` is empty until ER8.
- `disc_temperature` still reads the built-in G and σ (the sheet ledger, ER5).
- The band table (Planck and CIE) is still in the renderer: ER11b, with star and galaxy colour.
