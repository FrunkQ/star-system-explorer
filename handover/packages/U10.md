# U10: Browser campaign save (UI track)

Status: done 19 Nov 2026. The GM's campaign now survives a reload. It can be saved as a file, opened from one, or started fresh. Players joining a reopened campaign start from it and agree by state hash. It is built on the kernel's `export_chronicle` and `import_chronicle` (kernel track, PR 7).

## What it does

- **Kept in this browser.** After every change (state hash, pack stack, the ruler's time, undo and redo), the shell waits 600 ms, then writes one save to `localStorage` under `sse4.campaign`. The status bar shows "Kept HH:MM". If storage is full or blocked, it shows "Not kept", and the Campaign dialog says to download the save instead.
- **Reopening.** On load, the kept save is checked before anything else (`checkCampaignSave`, against `u:<universe id>`). Its pack stack goes back first (`stack_packs`, then `adopt_physics`), then the export is imported. The workspace overlay is restored: applied values, undo, redo and the ruler's time. The fixture facts are not entered again, because they are already in the chronicle. A note says when the save was kept and how many events it holds. The note adds a warning if the physics loaded now differs from the physics it was saved with (`stack_matches` false), or if the state hash differs from the one saved.
- **A save that will not reopen** (unreadable, wrong universe, or refused by the kernel, such as a damaged head) is moved to `sse4.campaign.set-aside`, never deleted. A fresh campaign then opens, and a note says what happened.
- **Campaign… dialog** (status bar):
  - Save campaign downloads `sse-campaign-<title>-<date>.json`.
  - Open a campaign takes a file. It is checked first. A bad file is refused with the reason and nothing changes. A good one shows its title, date and event count, and "Open it" keeps it and reloads.
  - Start fresh… asks once, then forgets the kept save and reloads Kestrel Reach as shipped.
- **Players.** The GM's sharing host now carries the reopened campaign's export on the manifest (`Manifest.opening_export`). A player's screen imports it before replaying the log, so it reaches "live" with the GM's hash. The packs on the manifest are the whole stack in force (opening, added and campaign). Sealed seats never get the manifest, as before.
- **Secrecy (design 8A, J1).** The kernel's export also carries the GM-only campaign record (`record`, `record_head`) once J1 lands. `publicExport` strips both, and `GmHost` applies it to whatever it is given, so the record never reaches the shared manifest. Seats get their share through `disclosures` on their own channel. The universe state hash does not depend on the record.

## The save format

`sse.campaign-save/1`, defined in `packages/ui-contract/src/campaign.ts`:
- `schema`;
- `saved_at` (the device's clock, presentation only);
- `title`, `root`, `state_hash`;
- `export`, the kernel's `sse.chronicle-export/1`, untouched;
- `workspace` {applied, undo, redo, now_yr};
- optional `stack` {added, campaign}.

The kernel keeps the pack stack apart from the chronicle, which is why the save carries it. The workspace overlay exists only while the Kestrel scene comes from the fixture. When the kernel builds that scene (K9), `applied` goes, and the save is the export plus the stack.

Code:
- `packages/ui-contract/src/campaign.ts`: save, check, file name, `publicExport`.
- `packages/ui-contract/src/session.ts`: `exportChronicle`, `importChronicle`, also on `ViewSession`.
- `packages/ui-contract/src/p2p.ts`: `opening_export` on the manifest, with import before replay.
- `packages/shell/src/campaign-store.ts`: storage, set-aside, download.
- `packages/shell/src/App.svelte`: reopen, autosave, Campaign dialog, note.

## Checks

- `ui-contract/test/campaign.test.ts` (Node, real kernel):
  - The round trip: facts entered, an edit, and the sample Sol adopted. The export is written as text and imported into a fresh kernel, giving the same state hash, Sol listed, and further edits applying.
  - A player's replica, from a manifest with `opening_export`, reaches live with the GM's hash after a further edit.
  - Bad saves (not a save, wrong universe, mismatched root) are refused.
  - `publicExport` drops the record.
  - A damaged export is refused with `bad_export`, and the open universe is untouched.
- `tests/ui/campaign.e2e.mjs` (Chromium locally; Chromium and Firefox in CI):
  1. Grow and add a system; the save is kept with the new hash.
  2. Reload: same hash, the system still on the chart, the note shown.
  3. A player's screen joins and agrees.
  4. Save campaign downloads the right file.
  5. Start fresh returns to the shipped hash.
  6. A junk file is refused.
  7. Opening the downloaded file restores the hash.
  8. A damaged kept save is set aside, and a fresh campaign opens.
- Screens are in `U10-screens/`.

## Not done, next

- Open what-if branches are not in the export (the kernel exports the main line only), so they are lost on reload. The Campaign dialog does not warn about this yet.
- Several campaigns per browser (a list instead of one slot) is still to do. So are IndexedDB for large campaigns, if localStorage's roughly 5 MB proves small, and sealed seats starting from a reopened campaign.
- Lenses, theme, sound and other per-device preferences were already kept separately (`prefs.ts`) and are not part of the save.
