# K2: addresses, quantities and units, keyed draws

Status: done (18 Nov 2026).

## What was built
`sse_core::address` (hierarchical addresses with an authored namespace), `sse_core::quantity` (dimensions, SI quantities, unit registry with cited constants, quantity kinds with checks), `sse_core::draw` (pinned keyed draws). Keyed draws join the cross-device harness.

## Design sections implemented
H5.1, H5.2, H5.3. ADR 0004 (draw algorithm). Choices the design left open: authored keys are `@n` (`body:@1`); generated keys are the decimal resolve index; patch keys may contain colons (segment splits on the first colon).

## Commands
```
cargo test -p sse-core
cargo run -p sse-cli --release -- harness
scripts/build-harness.sh && node tests/harness/run-node.mjs && node tests/harness/run-browsers.mjs
```

## Results
- Property tests (proptest, 256 cases each): draws identical in any call order; adding a stream leaves other streams unchanged; unit, bounded and normal draws in range; address text and CBOR round trips; unit conversions round trip; a quantity kind rejects every wrong dimension.
- Unit tests: au, solar mass, parsec to light years, Celsius offset; dimension mismatch rejected on add and on conversion; invalid addresses and stream names rejected.
- Golden draw value pinned in `draw::tests::golden_values_are_stable`.
- Harness: native, Node 22 and Chromium 157 agree on overall `e4f8ea73…d110a6`.

## Golden hashes
`tests/golden/harness.json` changed: new category `draws.keyed` (10,000 draws) and field `draw_cases`. All K1 category digests unchanged.

## Known limits
- Quantities are scalar only. Curves, distributions and enumerations (H5.2 non-scalar kinds) arrive with the flow values in K4 and the resolve work in K7.
- Constants were checked against their sources from memory of the IAU 2012 B2, IAU 2015 B2/B3 and CODATA 2018 values; the values used are the standard published ones and are listed in the module header.
