# V3: screens documents and the screens runtime

Status: done (18 Nov 2026), branch `claude/project-thread-adgixl`, on top of V12. U5 already built the composer. V3 adds what remained of H8.3: the rest of the screen document, one runtime that mounts a document wherever a screen is shown, and loading screens from documents.

## What was built
- **Screen documents (H8.3)** (`ui-contract/src/screen.ts`). A screen document now has:
  - `description`: a line for people and Orac.
  - `data_view`: the view the whole screen is seen through. The checker refuses a view the campaign does not have.
  - `bind` on each item: a TopicQuery of addresses (a subject and its children) and/or `kinds`, so one item shows only part of the scene. `boundScene()` applies it, and the scene's scope always stays in.
  - Layouts: `grid` (areas a to f), and `stack`, `flow` (wrapping tiles) and `page` (a printable report at reading width), which take areas 1 to 8 in order.
  - `checkScreen` also refuses non-documents, a missing id and bad `bind` keys.
- **One screens runtime** (`views/player-stack/src/ScreenRuntime.svelte`). It mounts a checked document onto a player scene:
  - It lays out the areas.
  - It shares the selection between views.
  - It gives each item its bound part of the scene.
  - It gives a box to views that declare `box: "fill"` (the chart). This is a new optional field in the view contract, so the runtime never names a view.

  The players page and the composer's preview both use it (the old Preview component is gone), so the preview is exactly what a player's device draws.
- **The players page loads its screen at runtime**:
  - `players.html?screen=<file>` loads a screen from `documents/`.
  - `?screen=composed` loads the one the composer handed over on this device.
  - The Bridge is the default.
  - A document's `data_view` fixes the view the scene is fetched through, and the Scanned control steps aside.
- **The composer opens screens from documents**:
  - A picker over the campaign's screen documents (new parameter `screens`).
  - Open a file, or paste a document. A broken one is opened with its reasons shown.
  - Layout and "Seen through" pickers.
  - Bound items are labelled.
  - "Show on the players page" hands the document to the players page on this device.
- **A second shipped screen**: `players.survey.screen.json`, "Tarn survey report". It is a page layout, seen through the survey view, with text and card bound to Tarn and a table of bodies.

## Not done
- Screens are not yet sent to players over the network (V4). The composer hands them over through this device's storage.
- The players page keeps the viewer's own theme choice. The document's `theme` is not applied as a default yet; that belongs with V11's style documents and V4.
- `bind.quantity_kinds` and `event_kinds` are accepted but not yet used by any player view.
