# J2: typed values, logic blocks, one condition language, keyed dice, engine blocks

Status: done (19 Nov 2026). Kernel track, PR into `main`. Design: `handover/design/SSE4-record-logic-programs-design.md` (track J) section 3, 8A.3, section 10 row J2.

## What was built
**Typed values on wires (`sse-flow`).** Optional fields that are skipped when absent, so every existing flow document, atom and hash is unchanged.
- `Shape` (`number`, `flag`, `choice`, `ref`, `text`, `record`, `list<shape>`, written as text) and `Val`.
- `Port.shape` and `Port.any_dim` (a logic number port of any dimension). `AtomDecl.class` (`logic` or `engine`) and `AtomDecl.dims` (`same`, `product`, `quotient`: how any-dimension outputs follow the inputs).
- `NodeDoc.config` (a logic block's settings) and `FlowInputDoc.shape` (typed flow inputs).
- `Atom` gained default methods: `eval_typed` (typed evaluation with a `Call`: environment, config, flow and node ids), `ports(config)` (ports that follow the config: a read's shape, an `and`'s arity) and `check_config`. Physics atoms need nothing new; numbers keep the original path.
- `Env`: a `World` (facts, whole-subject facts, parent facts, tags, children, kept values), the subject, `now_s`, `staying` (hysteresis), the universe seed (engine blocks only) and the table secret and counter (dice).
- Compile checks:
  - shape mismatches are edit-time errors, like dimension mismatches;
  - dimensions through any-dimension ports are checked in schedule order;
  - only numbers are published as quantities;
  - logic blocks cannot be solved for.
- `Evaluation::value_of`, `note_of` (an engine block's own explanation) and `evidence` (the world facts a result rests on, following only the inputs each block used).

**Crate `sse-logic`.**
- **The logic set** (`blocks.rs`), all `class: "logic"` with explain text and no citation rule:
  - compare: `logic.less`, `at_most`, `greater`, `at_least`, `equal`, `near`, `in_range` (factor and hysteresis margin as in K8);
  - combine: `logic.and`, `or` (2 to 16 inputs; stop at the first false or true, and only the inputs read are evidence), `not`, `count_true`;
  - choose: `logic.select`, `switch`, `lookup` (a table in the config), `first_match`;
  - numbers: `logic.add`, `subtract`, `multiply`, `divide`, `min`, `max`, `clamp`, `round`, `floor`, `ceiling`, `trunc`, `abs` (pinned maths);
  - lists: `logic.count`, `sum`, `any`, `all`, `filter`, `sort` (ties by address, then original order), `take`. Every list is at most 4096 long; a longer one is an error.
  - world: `world.read` (a fact as a shape, with `present`), `read_kept`, `has_fact`, `has_tag`, `children`, `now`, `staying`; plus `logic.const`.
- **One condition language** (`condition.rs`): `to_blocks` writes any K8 predicate (all, any, not, has, range, is, compare, near, tag, within) as a flow of these blocks. `filter` and `first_match` take a K8 predicate as their `where`. `SubjectWorld` presents a K8 subject as a `World`.
- **Dice** (`dice.rs`):
  - `chance.roll` (N dice of S sides) and `chance.draw` (a weighted table) are keyed draws: `draw(table_secret, subject, "<flow id>.<node id>.v1", counter * 128 + die)`.
  - No table secret in the environment means the roll is refused ("dice are rolled on the GM's machine only").
  - `table_secret(entropy)` makes the secret, `commitment(secret)` is what seats receive, and `verify` checks a reveal.
- **Engine blocks** (`engine.rs`), `class: "engine"`:
  - `engine.classify` (config `scheme`, optional `sticky` adding a `held` input) reads the subject's facts from the world. It outputs `class`, `classified`, `modifiers` and `fit`; its note is the atlas's own label with axes and runners-up.
  - `engine.place` (config `scheme`, `class`, `scope_au`, `force`) takes a system record and the universe seed from the environment. It outputs `outcome`, `label`, `recognised`, `fit` and `a_au`; its note is the whole C3 placement.
  - Both carry their own data (an atlas, the base-physics model), so the kernel adds them when it has a stack (J4). They are not in the kernel's registry yet.

**Kernel.** The logic set and dice are in the kernel's atom registry, so pack flows can use them. `atoms` lists `class`, `dims`, port `shape` and `any_dim` for logic blocks only, so physics atoms list exactly as before.

## Checks
- `sse-logic` (7 tests):
  - every block is logic and explained (44 blocks);
  - truth tables for every logic atom, including the inputs each combine used, hysteresis, configs refused with readable errors, and the over-long list. The test fails if an atom has no rows.
  - shapes and dimensions are checked at edit time: a flag into a number, a mass plus a length, a misspelt config key;
  - **K8 equivalence:** the rules pack's rules, 12 hand-written predicates (empty all and any, nesting past 16, every kind) and 9 more on the Solar System fixture. Each is checked on a grid of 720 subjects with facts present, absent, on the edge and of the wrong type, entering and staying. That is 10,000+ cases, all with identical answers and evidence, and the test checks that both answers and evidence are common;
  - **dice:** refused without the secret; the same dice whatever the node order; their own dice per node, turn and subject; other dice under the universe seed; the commitment verifies only the true secret; 1d6 shows every face; weights hold (storms 3 in 4);
  - **classify:** for the Solar System and reference exoplanet fixtures in all four schemes, the flow's class, modifiers, fit and note equal `Atlas::label`. A rule "is this world shirt-sleeve habitable?" wired as classify, then const, then equal answers the same. Stickiness through `held` matches the atlas, and an unknown scheme is refused;
  - **place:** all ten C3 golden cases through a flow equal `scenario::run`, note for note.
- Kernel `logic_blocks_are_listed`.
- Every existing flow, golden and contract hash is unchanged. `scripts/check.sh`, the JS contract (147 of 147 identical through the Web Worker), the harness in Node and Chromium, and the UI tests (131) pass.

No golden changed. No contract line changed: the contract asks `atoms` for named toy atoms only.

## Limits
- World reads give dimensionless numbers. A logic result wired into a physics port with a dimension is refused until a read can name its quantity kind (a later `kind` config).
- `map through a box`, `things within range of`, `distance between` and `known to audience` wait for J3 (boxes) and J4 (the GM-side world), which also adds the engine blocks to the kernel with the loaded atlas.
- Where the GM's machine keeps the table secret, and sending the commitment to seats, are J4 and UI work. J2 has the functions.
- `sort` orders numbers before text and records without the key last. Text is compared by bytes.
